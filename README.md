# ResumeIQ — AI Resume Analyzer & Job Recommendation System

A full-stack resume-to-job comparison app with a React/Vite dashboard, FastAPI API, SQLite persistence, PDF text extraction (PyMuPDF), Recharts visualizations, and local Ollama analysis. The dashboard uses real saved records; an empty database intentionally shows zero states.

## Requirements

- Python 3.11 or newer
- Node.js 20 or newer and npm
- [Ollama](https://ollama.com/) installed and running
- A local model with JSON/chat support (default: `llama3.2`)

## Windows PowerShell setup

Open three PowerShell terminals from the project root.

### 1. Backend

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
ollama pull llama3.2
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

If PowerShell blocks environment activation, run `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` in that terminal and activate again. The SQLite database is created as `backend/resume_analyzer.db` when the API starts. Set `OLLAMA_MODEL` in `backend/.env` to a model already installed locally; `OLLAMA_URL` can point to a different local Ollama endpoint.

### 2. Frontend

```powershell
cd frontend
npm install
npm run dev
```

Open the URL printed by Vite, usually http://localhost:5173. The frontend defaults to `http://localhost:8000/api`; set `VITE_API_URL` in a frontend `.env` if your API is elsewhere, then restart Vite.

### 3. Check services

- API health: http://localhost:8000/api/health
- Interactive API docs: http://localhost:8000/docs
- Frontend: http://localhost:5173

If health reports Ollama unavailable, start Ollama and run `ollama pull llama3.2` (or your configured model). The analysis endpoint returns a helpful 503 error rather than fabricating results when Ollama is unavailable.

## How the match score works

The score is `recognized skills present in both the resume text and job description / recognized skills in the job description × 100`. Skill recognition uses the vocabulary in `backend/app/services/analyzer.py`. The score is deterministic and does not trust a score generated by the LLM. When the job description contains no recognized skills, the score is 0 rather than a made-up score. This is a rough skill-overlap estimate, not a hiring prediction. Skills outside the current vocabulary can be missed.

Ollama provides contextual strengths, improvement ideas, a suggested professional summary, and related role titles. The app asks the model to return JSON, validates required fields, normalizes lists, and reports connection/response failures. Always review AI suggestions and verify every claim before using them in a resume.

## API endpoints

- `POST /api/resumes/analyze` — multipart PDF (`file`), `job_title`, and `job_description`
- `GET /api/resumes?q=&sort=newest&skip=0&limit=10`
- `GET /api/resumes/{id}`
- `DELETE /api/resumes/{id}`
- `GET /api/dashboard/stats`
- `GET /api/dashboard/activity`
- `GET /api/dashboard/analytics?period=day|week|month|year`
- `GET /api/jobs/recommendations`
- `GET /api/health`

## Notes

- PDF text extraction is not OCR. Scanned/image-only PDFs need OCR before analysis.
- Maximum PDF upload size is 8 MB; job description length is limited to 10,000 characters in the UI.
- The app stores resume text and job descriptions in SQLite. Protect the database file and do not expose the API publicly without authentication, authorization, TLS, and appropriate data-retention controls.
- This starter app has no authentication/multi-user isolation. It is intended for local development and portfolio use.
